# BONUS

BONUS 是一款使用两副扑克牌和一枚六面骰子的 2D 出牌游戏，使用 Godot 4.7 与 GDScript 开发。玩家根据骰子点数决定出牌数量，并通过让其余玩家全部 PASS 来触发可以自由选择牌型的 BONUS 阶段；最先打完手牌的玩家获胜。

## 当前状态

当前版本为 `0.5.38`，已经具备完整的 2～4 人单机牌局、引导教程和局域网联机原型。主要功能包括：

- 两副牌、逐张开局发牌、17 张初始手牌、自然大小王和可选万能牌规则；
- 骰子决定出牌数量、完整牌型识别与比较、跟牌、PASS、BONUS 和多解选择；
- 人数、规则和八位种子配置，以及相同种子的确定性牌局；
- 可替换 AI 策略、自动掷骰、自动跳过和 AI 托管；
- 局域网房间、准备状态、AI 座位、权威房主、回合计时、断线接管与重连；
- 可视化教程流程编辑器、事件步骤、条件分支、输入锁定、指示与高亮；
- 自动存档和未完成牌局恢复，以及对局、连胜和操作统计；
- 结算前 AI 手牌摊开、结算统计、新连胜纪录提示和再来一局流程。

当前构建已经接入主菜单与游戏界面 BGM，以及界面、卡牌、骰子、回合、BONUS 和结算音效。BGM 统一播放到 `Music` 总线，场景切换使用交叉淡入淡出；音效统一由 `AudioService` 播放到 `SFX` 总线，同类素材通过 Godot `AudioStreamRandomizer` 随机选取并进行轻微音调变化。BONUS 和结算阶段会暂时压低背景音乐，避免重要音效被掩盖。事件映射见 [音效事件表](docs/sound_cue_catalog.md)。

## 开发环境

- Godot 4.7.1 或同一兼容版本
- GDScript
- 当前开发和首个发行版本以 Windows 桌面与鼠标操作为目标

用 Godot 编辑器导入本目录中的 `project.godot` 即可打开项目。

运行项目后进入 `app/app.tscn` 主界面。首次启动会保留“教程”“设置”和“统计数据”，进入过教程后解锁单人及多人游戏。选择“单人游戏”可设置人数、种子和可选规则；如果存在未完成存档，会先询问继续还是新开。相同自定义种子会生成相同的洗牌与后续随机序列。

轮到南家掷骰时，点击 Header 和弹出界面以外的画面区域即可掷骰；“提示”会选择一手合法牌。单击切换选择，在画面任意位置按住左键后划过多张手牌可连续选择，右键清空选择。手牌始终自动排序；开启“双击出牌与过牌”后，左键双击空白区域会打出当前选择，右键双击空白区域会直接过牌。

设置只在点击“应用”后生效，音量调整除外；支持游戏速度、分辨率、窗口/全屏、中英文、状态提示、双击操作和简化牌面。“应用”不会关闭设置面板，关闭或点击面板外区域可返回牌局。编辑器运行时必须关闭 Game 窗口的嵌入模式，否则 Godot 不允许运行时调整窗口。

## 用户数据

设置、进度、统计和未完成牌局不会写入安装目录，而是使用 Godot 的 `user://`。Windows 默认位置为：

`%APPDATA%\Godot\app_userdata\Bonus\`

| 文件 | 内容 |
| --- | --- |
| `bonus_settings.cfg` | 分辨率、语言、音量和游戏设置 |
| `bonus_progress.cfg` | 教程状态及主菜单解锁进度 |
| `bonus_statistics.cfg` | 生涯对局、连胜和操作统计 |
| `bonus_save.json` | 未完成的单人牌局和本局统计 |

这些文件可跨游戏更新保留，并可在接入 Steam 后作为 Steam Cloud 的同步对象。发行版保持 `bonus.exe` 与 `bonus.pck` 分离，利用 SteamPipe 的块级增量更新降低补丁下载量。详见 [分发与持久化约定](docs/distribution.md)。

## 项目结构

| 目录 | 用途 |
| --- | --- |
| `app/` | 程序入口及顶层场景组合 |
| `assets/` | 项目实际使用的美术、音频、字体和主题资源 |
| `autoload/` | 设置、音频、存档、统计与局域网等跨场景服务 |
| `core/` | 不依赖界面、AI 或网络的游戏状态、规则和牌局流程 |
| `features/` | 主菜单、游戏、设置、教程等用户可见功能 |
| `ai/` | AI 接口实现与可替换策略 |
| `localization/` | Godot 翻译源文件与各语言资源 |
| `multiplayer/` | 联机协议、同步逻辑和传输适配器 |
| `shared/` | 多个功能共同使用的界面组件 |
| `tests/` | 单元测试与集成测试 |
| `docs/` | 工程文档，不参与 Godot 资源导入 |

完整说明见 [架构说明](docs/architecture.md)、[游戏场景开发路径](docs/game_scene_roadmap.md)、[AI 策略接口](docs/ai_strategy_api.md)、[教程创作指南](docs/tutorial_authoring.md)、[分发与持久化约定](docs/distribution.md) 和 [音乐与宣传视觉方向](docs/creative_direction.md)。

## 资源与参考代码

- 游戏规则以项目外部维护的正式 Markdown 规则为唯一依据。
- 旧版本代码只用于了解已有功能，不复制其架构或实现。
- 扑克牌、骰子和筹码只从提供的 `Card_Game_GFX` 素材库中选取。仅将实际使用的文件复制到 `assets/art/`，不提交整套源素材库。

## 基本约定

- 文件、目录、变量和函数使用 `snake_case`。
- 类名、节点名和枚举名使用 `PascalCase`。
- 信号使用过去时命名，例如 `turn_started`、`card_played`。
- 新代码使用静态类型；公开接口必须写明参数和返回值类型。
- 场景专属脚本与场景放在同一功能目录。
- 不使用含义宽泛的全局 `manager` 保存牌局状态。
- 安装目录只保存只读发行内容；运行时可变数据统一写入 `user://`。
