# 局域网联机架构

## 连接方式

局域网模式使用 Godot 4.7 的 `ENetMultiplayerPeer` 和高层多人 API。房主监听指定端口，其他玩家通过房主的 IPv4 地址和端口加入。默认端口为 `9077`，可用范围为 `1024` 至 `65535`。

若系统防火墙拦截连接，需要允许 Bonus 接收专用网络中的入站 UDP 流量。公网连接、NAT 穿透和 Steamworks 不属于当前局域网传输层的职责。

## 模块职责

- `multiplayer/transports/lan_transport.gd`：创建和关闭 ENet 服务端或客户端。
- `multiplayer/lobby/lan_room_state.gd`：管理位置、成员、准备状态、AI、房间配置和重连占位。
- `autoload/lan_multiplayer_service.gd`：处理 RPC、权威牌局、回合计时、断线接管和定向同步。
- `multiplayer/protocol/public_game_snapshot.gd`：为每个接收方生成独立的公开快照。
- `multiplayer/session/network_game_view.gd`：将公开快照转换为只用于客户端展示和本地牌型提示的视图。
- `features/multiplayer/lan_panel.*`：主界面的创建房间、加入房间和等待房间界面。

## 权威端规则

房主是唯一持有真实 `GameSession` 的节点。客户端只发送“掷骰”“出牌”和“过牌”的操作意图。房主根据 RPC 的实际发送者确定其位置，并使用核心规则再次校验当前阶段、行动顺序、手牌归属、牌型和牌型解读。

客户端不能决定骰子结果、摸到的牌、回合流转或胜负。非法操作不会改变权威状态，只会向请求方返回错误键。

## 信息边界

每个玩家收到的快照都单独生成，其中包括：

- 当前阶段、行动玩家、掷骰玩家、骰子点数和 BONUS 状态；
- 所有玩家的手牌数量、连接状态和公开身份；
- 接收方自己的完整手牌；
- 桌面上已经公开的牌和牌型；
- 牌堆及弃牌堆的数量、房间规则、种子文本和回合截止时间。

快照不会包括牌堆顺序、牌堆中的牌面、其他玩家的手牌、随机数状态或完整 `GameSession` 存档。客户端用于展示的对手手牌只是按数量生成的占位对象，不能还原真实牌面。

## 断线、重连与超时

每位真人玩家加入房间时获得一个随机重连令牌。ENet 的 peer ID 发生变化后，玩家仍可使用原玩家 ID 和令牌取回原位置。对局中的断线位置不会被移除，默认 AI 会立即接管；重连成功后会恢复真人控制。

真人玩家超过房主设置的 15、30 或 60 秒限制后，默认 AI 会完成该玩家当前整段回合。房主断线时没有可继续信任的权威状态，因此所有客户端结束本局并返回主菜单。

## 验证

`tests/multiplayer/test_lan_room.tscn` 覆盖房间容量、随机空位、准备门槛、AI、重连和快照隐私。`tests/multiplayer/lan_native_probe.tscn` 用两个原生 Godot 进程验证本机 ENet 连接及双向权威动作。
