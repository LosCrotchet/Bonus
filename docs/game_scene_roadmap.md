# 游戏场景开发路径

## 当前进度

版本 `0.5.6` 已完成程序外壳、主菜单、2～4 人单人规则配置、完整牌局、逐张开局发牌、自然大小王、可选万能牌、BONUS、牌型浏览、可替换 AI、事务式设置、多语言、结算返回和场景转场。手牌支持扇形自适应、固定排序、摸牌与出牌演出、从画面外开始的连续划选，以及可选的全局左右键双击操作。界面、卡牌、骰子、回合、BONUS 与结算音效已接入统一的并发播放服务。

## 最终目标

直接运行 `features/game/game_scene.tscn` 时，玩家可以用鼠标完成一局游戏：创建两副牌的牌堆、初始化 2～4 名玩家、每人发 17 张牌、按正式规则进行回合，并在某位玩家合法清空手牌后看到结算结果。

首个可玩版本由一名本地玩家和基础 AI 组成。AI 与联机玩家使用同一动作接口，避免以后重写牌局流程。

## 里程碑 0：工程骨架

本阶段建立目录、依赖边界、编码规范和开发顺序，不实现牌局。

完成标准：

- 项目目录与架构文档进入版本库。
- Godot 能正常扫描项目。
- 外部参考代码、官方文档和未使用素材不进入项目仓库。

## 里程碑 1：无界面的牌局基础

先实现可在无窗口环境运行的核心数据：

1. `CardData`、牌面和花色枚举。
2. `DeckFactory` 创建两副完整扑克牌，共 108 张，每张牌具有唯一 ID。
3. 可注入随机源和确定性洗牌。
4. `PlayerState` 与 `GameState`。
5. `GameSession.start_game()` 初始化 2～4 名玩家并轮流发牌，每人 17 张。
6. 摸牌堆与弃牌堆的基本操作和牌堆重建。
7. 手牌清空与万能牌惩罚后的胜负判定入口。

测试重点：总牌数不变、ID 不重复、各玩家手牌数量正确、固定种子结果可复现、非法玩家数量被拒绝。

## 里程碑 2：规则与回合状态机

按照正式 Markdown 规则实现：

1. 1～6 张牌的全部合法牌型。
2. 顺子和连对不含 `2`，且不能跨首尾。
3. 组合牌型的主体比较。
4. 四条、五条和六条对同张数其他牌型的压制。
5. 单张大小王自然比较；纯大小王可混合组成最高对子、三条或四条，且不计作万能牌。
6. 三条可压过三张顺子。
7. 大小王与普通牌组合时可选作万能牌，以及实际使用万能替代完成最后一手时的可选摸牌惩罚。
8. 掷骰、出牌、跟牌、不出牌、摸 3 张和 BONUS。
9. 弃牌回收及胜者确认。

所有状态变化都由 `GameAction` 驱动。完成标准是一组集成测试可以从开局推进到结算，且不需要加载任何场景。

## 里程碑 3：基础 AI

实现一个简单但合法的 AI 策略：

- 只从规则核心返回的合法动作中选择。
- 优先减少手牌数量，不追求复杂策略。
- 使用相同的状态快照和动作格式，不访问场景树。
- 策略同步返回纯数据决策，思考等待与动画由调用方异步调度；耗时算法或远端服务以后通过独立代理适配。

基础 AI 的目标是让游戏场景可以完整体验，不代表最终难度设计。

## 里程碑 4：可玩的游戏场景

创建 `features/game/game_scene.tscn`，初步布局如下：

```text
┌──────────────────────────────────────────────────────────┐
│ 回合与状态提示                     摸牌堆数量 / 设置入口 │
│                                                          │
│                  对手席位与剩余牌数                      │
│                                                          │
│      左侧席位          当前出牌 / 骰子        右侧席位   │
│                                                          │
│                  本地玩家手牌区域                        │
│                  [提示] [不出] [出牌]                    │
└──────────────────────────────────────────────────────────┘
```

场景分为以下组件：

- `GameScene`：连接牌局与显示层，不包含规则判定。
- `TableView`：牌桌中央区域、摸牌堆、弃牌和骰子。
- `PlayerSeatView`：玩家名称、状态和剩余牌数。
- `HandView`：根据可用宽度排列手牌并处理鼠标选择。
- `CardView`：显示单张牌的正背面、悬停和选中状态。
- `ActionBar`：提示、不出和出牌操作。
- `ResultDialog`：胜者、再来一局和返回菜单。

扑克牌和骰子素材从 `Card_Game_GFX` 中选定后导入 `assets/art/`。界面使用锚点和容器适配窗口，不依赖固定屏幕坐标。

## 里程碑 5：完整鼠标交互与反馈

- 单击卡牌切换选中状态。
- 拖过多张手牌可连续选择或取消选择。
- 手牌始终按点数和花色稳定排序，不提供拖拽重排。
- 开启对应设置后，左键双击非手牌区域可提交当前选择；未选牌时忽略。右键双击非手牌区域始终尝试过牌。
- 不合法操作不会提交，并给出简短、明确的原因。
- 非当前玩家回合时禁用手牌和行动按钮。
- 发牌、出牌和摸牌动画只表现已经确认的状态变化。
- 动画期间保持稳定布局，不允许重复提交动作。

完成标准：玩家无需调试按钮或键盘即可完成整局游戏。

## 里程碑 6：程序外壳

本里程碑已在 `0.5.1` 完成：

- `app/app.tscn` 与场景导航。
- 主菜单：单人游戏、多人游戏占位、设置和退出。
- 单人游戏：人数、牌堆大小王、万能牌、末手万能牌摸两张、顺子带 `2` 和 `7-x` 摸牌规则。
- 设置：游戏速度、窗口模式、分辨率、语言、状态提示、自动跳过和双击操作。
- 主菜单与牌局之间的无闪断过渡，以及常驻版本号。
- 教程入口预留，不提前实现无需求内容。

## 后续扩展

### 多人联机

先冻结 `GameAction` 和状态快照格式，再实现权威端与传输适配器。联机代码不得复制规则判定，也不得让客户端直接修改牌局状态。

### 自定义 AI

在玩家代理接口稳定后增加策略注册表。自定义算法只需要实现决策接口并声明名称、版本及可配置参数，无需修改 `GameSession` 或游戏场景。

## 每阶段交付流程

每个里程碑都按以下顺序完成：

1. 为状态与行为写明输入、输出和边界条件。
2. 先实现并验证纯逻辑，再连接场景。
3. 使用 Godot MCP 运行项目并检查调试输出。
4. 对界面阶段检查常用桌面分辨率下的布局。
5. 确认无临时文件和未使用资源后提交并推送当前开发分支。
